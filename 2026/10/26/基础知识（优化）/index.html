1. 内存和帧率

由于硬件的影响，应用程序不可能无限开辟内存，所以内存是应用程序效率的主要数据之一。内存太高可能导致应用程序崩溃，会导致内存碎片化，影响下一次使用内存的寻址时间，还会导致垃圾清理消耗太多时间。

帧率和内存是游戏性能分别在时间和空间上的两个数据表现。而这两个数据表现是由一系列其他因素导致的。

为了知道哪些因素导致了性能的消耗，可以使用性能优化工具来查看。比如 RenderDoc，Intel GPA，Unity Profiler 等。

2. 优化顶点数据

（1）不对不需要的数据进行导出，比如没有用到 2UV 就不输入 2UV，没有用到法线就去掉法线，没有顶点色信息就去掉顶点色等等。

（2）顶点数据压缩，可以提高数据从 CPU 传入 GPU 的速度。

（3）坐标数据，使用更节省的数据类型，减少每个顶点数据占用的字节数。

3. Draw Call

（1）减少场景中的物体数量。不在摄像机的可视范围内不对其进行渲染。

（2）合批 Draw Call。如动态合批，静态合批，代码合批。这些合批的基本条件是使用相同的材质。

4. 面数

（1）一般在项目中会确定模型制作时的面数要求，在前期就规定好同屏面数的限制，而一些没有经验的项目往往就要花费数倍的时间和金钱去进行返工。

（2）面数 LOD：现在引擎一般都会提供 LOD 功能，根据摄像机距离的不同来使用不同的 LOD Level 的模型。

5. Shader

（1）Shader 复杂度：一般来说，Shader 的指令个数可以粗略表示 Shader 的复杂度。要降低复杂度，要少用复杂计算的函数，反三角函数以及循环指令的消耗都特别大，要尽量少用。

sin, cos, log, sqrt, pow, atan, atan2 使用 SFU 进行计算，通常需要花费几个 ALU 甚至几十个 ALU，尽可能避免。比如 pow(x, 5)，就可以写成 x2 = x*x; x5 = x2*x2*x 这样。

类型转化不一定是免费的（half→float, vec3→vec4），减少无意义的类型转换。

saturate, negation, abs 是免费的，clamp, min, max 不是。不要负优化。

尽量使用"足够用"的数据类型，如果使用 half 足够的话，就没有必要用 float。

（2）Shader LOD：给不同性能的设备提供高中低配置的 Shader 版本。

（3）在 CPU 性能不错的情况下，能在 CPU 计算的就不在顶点着色器计算，能在顶点着色器计算的就不在片元着色器计算。

（4）使用适合的数据精度。

6. 贴图

（1）在移动端，ASTC 是首选的纹理压缩格式。

（2）尺寸：图片越大，消耗越大。最好是根据实际的运行平台来确定适合的贴图大小。

（3）采样滤波（Filter）：现在常见的滤波方式中性能消耗：Anisotropic ⇒ Trilinear ⇒ Bilinear ⇒ Linear ⇒ Point，而更高的消耗也意味着更高的精度，更好的效果。

（4）Mipmap：当摄像机离图片距离更远时，引擎会自动采用更低精度的 Mipmap，可以有效减少渲染消耗。

（5）合并多个单通道贴图，可以降低内存消耗。

7. Overdraw

（1）使用透明渲染时会出现。为了绘制透明物体背后的物体，所以不能裁剪掉背后的物体，而多个透明物体互相叠加时，性能消耗更为恐怖。

（2）所以要减少透明物体，限制透明物体的重叠。

（3）合理使用模型增大贴图实际使用画面占比。

8. 分辨率

（1）分辨率越高对于 GPU 的性能要求越高，对于分辨率高但是 GPU 比较差的机型进行降低渲染分辨率可以提高帧率。

9. 剔除

（1）主要有：视锥体剔除、遮挡剔除、背面剔除、深度剔除。

10. 光照

（1）在前向渲染中，光源照射到的每一个物体都会增加额外的渲染开销。

（2）在延迟渲染中，光源在屏幕上覆盖的面积越大，渲染成本就越高。
